From Keystroke to Draft

You type a question and press Enter. A few moments later a draft appears. Here is every hand that message passes through.

What this app actually is

AetherLink is a small practice chat for a support-desk workshop. There is exactly one fake customer complaint on screen, and you ask an AI "coordinator" to prepare a reply for a human to check. It never sends anything to anyone.

🎫
One made-up ticket: WL-1026

Maarten says he was charged twice and wants it fixed today. That is the only ticket the app will ever accept.

🔀
Two modes: Demo fixture and Claude Code

Demo returns the same canned answer every time. Claude Code asks a real AI model running on your own machine (still marked experimental).

✋
A human gate on every answer

Every reply is labelled a draft that a person must approve. The code refuses to show anything that says otherwise.

The moment you press Enter

Think of the message as a baton in a relay race. The first runner is the chat page in your browser. Its only job is to package your words and hand them to the next runner, the server.

src/main.tsx 
      const response = await fetch("/api/chat", {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({ mode, message, ticket }),
      });
PLAIN ENGLISH

Send a request to the address /api/chat and wait (await) until the server answers.

Use POST, because we are handing over data, not just asking to read a page.

Put a label on the package saying the contents are JSON.

The package holds three things: which mode you picked, what you typed, and the whole WL-1026 ticket.

Done packing; off it goes.

💡
The browser never talks to the AI

Notice the address is /api/chat on your own machine, not an AI company's website. Keeping the model call on the server means no password or API key ever reaches the page, where anyone could read it.

The three-line heart of the server

When the baton arrives, the server's endpoint handler does the whole middle of the relay in three lines. Everything else in server/index.mjs supports these.

server/index.mjs 
      payload = validateChatRequest(await readBody(request));
      const result = payload.mode === "demo" ? { text: JSON.stringify(validateDecision(JSON.parse(demoReply(payload)), payload.ticket), null, 2) } : await liveReply(payload);
      sendJson(response, 200, { mode: payload.mode, ...result });
PLAIN ENGLISH

Read the incoming package, then hand it to the guard. If the guard objects, we jump straight to the error path and nothing else runs.

Fork in the road: in demo mode, build the canned draft and run it through the same answer-checker the real model faces. In live mode, go ask Claude (and wait).

Reply with status 200 ("all good") plus the mode and the checked result.

🔎
Even the fake answer gets checked

The demo draft is hard-coded, yet it still passes through validateDecision. That keeps both paths honest: if someone edits the canned text into something unsafe, the demo breaks loudly instead of quietly teaching bad habits.
