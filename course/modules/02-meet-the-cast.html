Meet the Cast

A film set runs on a call sheet: every crew member has one job and knows who they report to. This repo works the same way.

The call sheet (who lives where)

On a film set, the camera operator never touches the lighting rig. Knowing who owns which job lets you tell an AI "change this in the guard, not the page," and get a precise edit instead of a sprawling one.

How two programs start as one

During development you run a single command, yet two programs start. scripts/dev.mjs is the stage manager who calls both actors onto set, and vite.config.ts tells Vite where to send API traffic.

scripts/dev.mjs L3-4 · vite.config.ts L6 
const server = spawn(process.execPath, ["--env-file-if-exists=.env", "server/index.mjs"], { stdio: "inherit" });
const vite = spawn("npx", ["vite"], { stdio: "inherit", shell: true });
  server: { port: 5173, strictPort: true, proxy: { "/api": "http://127.0.0.1:8787" } },
PLAIN ENGLISH

Start the API server as a separate process, loading settings from a .env file if one exists.

Also start Vite, sharing the same terminal output so you see both logs.

Last line is from vite.config.ts: serve the page on port 5173, and act as a proxy: forward every /api request to the server on 8787.

💡
Dev and production take different doors

With npm run dev, you open port 5173 and Vite forwards to 8787. With npm run build + npm start, you open 8787 directly and the server hands out the built files from dist/ itself. Same API, two front doors. If "the page loads but chat fails" in dev, suspect the proxy or a server that did not start.
